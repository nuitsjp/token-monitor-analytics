<a id="uc-1"></a>
### UC-1. Hub を登録する

- 主アクターと目的: 利用者。Web 画面から Hub を登録し、その Hub からの収集を開始する。[設計方針 第1節](design-policy.md#1-目標と機能範囲)「複数 Hub の一括管理」の登録と一覧表示に対応する。
- 前提: アプリが起動している。利用者認証はない（[U12](../PLAN.md#u12)）。
- 主成功系列（UC-1-M）:
  1. 利用者は画面の「Hub 管理」で、登録済み Hub の一覧（ID、URL、接続状態、収集状態）を見る。
  2. 利用者は Hub の ID、URL、共有シークレットを入力して「登録」を選ぶ。
  3. システムは入力を検証し、接続設定を保存し、Hub を登録して収集を開始する。
  4. 一覧に新しい Hub が現れ、接続後に現在値が表示される。
  5. 再起動後も登録した Hub が一覧にあり、収集が続く。
- 拡張:
  - UC-1-X1: 2 で入力が不正（ID の重複または形式、URL の形式、シークレットの形式）なら、システムは理由を表示して保存しない。
- 受け入れ条件: 登録から10秒以内に一覧へ反映される。不正入力は保存されない。共有シークレットは画面・ログ・API 応答に出ない。同一オリジン外からの登録要求は拒否される。再起動後に登録が維持される。他の Hub の収集と閲覧に影響しない。
- 実現パターンと逸脱: [P-1](architecture.md#patterns) / 逸脱: なし
- 合意記録:

  - 合意した系列: UC-1-M、UC-1-X1
  - 論点と回答: (1) UC-1-X1 をモックの合意範囲に含める: 既定でよい。(2) 登録直後の表示は 1 行で足りる: 既定でよい。(3) 練習用 Hub のポート 8788 とシークレット表示はモック構成に限る: 既定でよい。
