# UC-1. Hubの最新情報をローカルに保存する

- 主アクター: 利用者。起動後の受信・保存は自動で行います。
- 目的: Hubの最新情報をローカルで利用できるようにします。
- 前提: 接続する1つのHubの安定したID・表示名・URLと認証情報がサーバー側に設定されています。
- 起動条件: 利用者がアプリケーションを起動します。
- 保存対象: Hubが配信する利用量、上限、端末状態等の最新状態と、受信元Hub・受信時刻。受信イベントの履歴は保存しません。

## 主成功系列

UC-1-M / UI確認: 不要。画面操作を伴わないため、段階2・3を省略します。

| 手順 | アクター | 操作・処理 |
| --- | --- | --- |
| 1 | アプリケーション | 起動時に接続設定を読み、HubのIDと表示名を登録してからSSE接続する |
| 2 | アプリケーション | 初回の全体状態を受信し、形式と必須項目を検証する |
| 3 | アプリケーション | 受信元Hubに紐づけ、最新状態と受信時刻を一括で保存する |
| 4 | アプリケーション | 以後の通知を受信順に検証し、DBの最新状態へ反映する |
| 5 | アプリケーション | コミット完了後に保存成功を記録し、受信を継続する |

## 受け入れ条件

- 初回および更新後の最新状態を、保存処理とは別のDB接続から読み取れます。
- 未受信でもHubを識別できます。同じHub IDでの再起動やURL変更でも保存状態を維持し、別の提供元には別のIDを使います。
- 同じ情報を再受信しても利用量が二重加算されません。
- 不正な通知や保存失敗では、最後に保存できた有効な状態を維持します。
- アプリケーションを終了・再起動しても保存済みの状態が残ります。
- 認証情報をログや受信データの保存内容に含めません。
