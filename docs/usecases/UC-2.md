# UC-2. 利用状況を閲覧する

- 主アクター: 利用者。
- 目的: 登録Hubから受信済みの最新利用状況を、ひとつの画面で確認します。
- 前提: アプリケーションが起動し、Hubが接続設定へ登録されています。
- データ取得: 画面を開いた時に一度取得します。自動更新と手動更新は行いません。

## 主成功系列

UC-2-M / UI確認: 必要。カードの内容、複数Hubの配置、未受信状態、画面全体の読みやすさをモックで確認します。

| 手順 | アクター | 操作・処理 |
| --- | --- | --- |
| 1 | 利用者 | アプリケーションのトップ画面を開く |
| 2 | 画面 | 利用状況取得APIを一度呼び出す |
| 3 | アプリケーション | 現在登録されているすべてのHubについてSQLiteの最新状態を読み取る |
| 4 | アプリケーション | Hub名、今日の使用トークン数、今日の推定コスト、端末数、データ更新日時を返す |
| 5 | 画面 | Hubごとに1枚のカードを表示する |

未受信のHubは、数値とデータ更新日時の代わりに「まだ情報を受信していません」と表示します。取得に失敗した場合はカードを表示せず、画面全体に「利用状況を取得できませんでした」と表示し、保存済みデータと接続設定を変更しません。

## 受け入れ条件

- 現在の接続設定に登録されているすべてのHubを区別して表示し、Hub数を固定しません。
- 過去に設定から外れ、DBだけに残っているHubは表示しません。
- 受信済みのHubには、今日の使用トークン数、今日の推定コスト（USD）、端末数、データ更新日時を表示します。
- データ更新日時には、受信データの `stats.updatedAt` をブラウザーのローカル日時に変換して使用します。
- 数値とデータ更新日時はSQLiteに保存された最新状態と一致します。
- 未受信のHubには、Hub名と未受信メッセージを表示します。
- APIは接続先URLや認証トークンを返しません。
- 画面表示によってSQLiteの内容は更新されません。
- 画面を再読み込みすると、その時点でSQLiteに保存されている最新値を表示します。
- 自動更新、手動更新、履歴、内訳、利用上限、グラフは対象外です。
