# UC-2. 利用状況を閲覧する

- 主アクター: 利用者。
- 目的: 登録Hubとデバイスの最新状態を、ダッシュボードのひとつの画面で確認します。
- 前提: アプリケーションが起動し、Hubが接続設定へ登録されています。
- データ取得: 画面を開いた時に一度取得し、UC-2-X1で以後の保存通知を反映します。手動更新は行いません。

## 主成功系列

UC-2-M / UI確認: 必要。A案（Workspace）をトップ画面に採用し、Hub・デバイスの配置、未受信状態、画面全体の読みやすさを確認します。

| 手順 | アクター         | 操作・処理                                                                  |
| ---- | ---------------- | --------------------------------------------------------------------------- |
| 1    | 利用者           | アプリケーションのトップ画面を開く                                          |
| 2    | 画面             | 利用状況取得APIを一度呼び出す                                               |
| 3    | アプリケーション | 現在登録されているすべてのHubについてSQLiteの最新状態を読み取る             |
| 4    | アプリケーション | Hub名、受信状態、デバイス情報、期間別トークン数・推定コスト、データ更新日時を返す |
| 5    | 画面             | 登録Hubとデバイスを区別してダッシュボードのHub・デバイス欄へ表示する        |

未受信のHubは「まだ情報を受信していません」と表示します。取得に失敗した場合はHub・デバイス欄に「Hub・デバイスを取得できませんでした」と表示し、保存済みデータと接続設定を変更しません。

## 拡張系列

### UC-2-X1. 閲覧中の利用状況を自動更新する

- 主アクター: 利用者。
- 目的: 再読み込みせずに最新の保存済み利用状況を確認します。
- 前提: UC-2-Mの初回API取得に成功し、Hub・デバイスを表示しています。
- 分岐点: UC-2-Mの手順5の後。
- UI確認: 必要。数値の更新、期間選択の維持、切断時の表示を確認します。

| 手順 | アクター | 操作・処理 |
| --- | --- | --- |
| 1 | 画面の共通受信処理 | 更新通知への接続を開始する |
| 2 | アプリケーション | 接続時点の最新保存値を通知する |
| 3 | 画面の共通受信処理 | 共有データを受信した全体状態で置き換える |
| 4 | 画面 | 共有データを参照する各コンポーネントの数値・構成比・受信状態を更新する |
| 5 | 画面 | UC-1の保存後通知ごとに手順3・4を繰り返す |
| 6 | 画面の共通受信処理 | 画面を閉じたら共通接続を終了する |

受け入れ条件:

- 実データに接続済みのHub別トークン数・推定コスト・合計・構成比、Hub数・デバイス数・取得時刻が自動更新されます。
- 未受信Hubは、初回保存の通知を受けた時点で受信済みの表示に変わります。
- TODAY・MONTH・TOTALの選択を維持し、選択中の期間の値を更新します。
- ブラウザーのアプリケーションごとに接続を1本だけ持ち、コンポーネント数に応じて増やしません。後から表示するコンポーネントも共有データの最新値を参照します。
- 初回API取得と通知接続の間の更新は、接続時の最新保存値で補います。
- 切断時は最後の値を保持して「再接続中」と表示し、再接続後に最新保存値へ追いつきます。
- 受信ごとに全体を置き換え、使用量を加算しません。
- 手動更新と、固定サンプルの他パーツの実データ化は対象外です。初回取得失敗の振る舞いはUC-2-Mを維持します。

### UC-2-X2. 全Hub統合情報を表示する

- 主アクター: 利用者。
- 目的: 画面上部の主要指標（トークン、推定コスト、アクティブ日数）に、全Hubの受信情報に基づく集計結果を表示します。
- 前提: UC-2-Mによりトップ画面が開かれ、Hub情報が取得されている。
- 分岐点: UC-2-Mの手順5の後、またはUC-2-X1の更新通知受信時。
- UI確認: 必要。画面上部KPI（トークン・推定コスト・アクティブ日数）の実データ反映、期間切り替えへの連動、未受信時の表示を確認します。

| 手順 | アクター | 操作・処理 |
| --- | --- | --- |
| 1 | 画面 | 共有データ（全Hubの最新状態）から、選択中期間の全Hub合計トークン数と合計推定コストを算出する |
| 2 | 画面 | 共有データから、全Hubのアクティブ日数を集計する |
| 3 | 画面 | 画面上部の主要指標欄（トークン、推定コスト、アクティブ日数）へ算出した値を表示し、「保存値」バッジを表示する |
| 4 | 利用者 | 期間（TODAY / MONTH / TOTAL）を切り替える |
| 5 | 画面 | 選択された期間に合わせて、トークン数・推定コスト・アクティブ日数を再計算して表示を更新する |
| 6 | 画面 | UC-2-X1によるデータ更新を受信した際、手順1〜3を自動で再実行する |

受け入れ条件:

- 画面上部の「トークン」「推定コスト」「アクティブ日数」が固定サンプルから保存データに基づく値に置き換わります。「保存値」ラベルはすべて削除し、未更新のパーツにのみ「固定サンプル」を表示します（実データ反映済みの箇所はラベルなし）。
- トークン数は、受信済み全Hubの選択期間（TODAY・MONTH・TOTAL）の `totalTokens` の合計値を、カンマ区切りの整数で表示します。
- 推定コストは、受信済み全Hubの選択期間の `costUsd` の合計値をドル換算（`$X,XXX.XX` 形式）で表示します。
- アクティブ日数は、全Hubの受信データから算出した日数を整数で表示します（受信済みHubの `activeDays` の最大値）。
- 受信済みHubが0件の場合は、トークン `0`、推定コスト `$0.00`、アクティブ日数 `0` とし、未受信Hubは集計に含めません。
- 期間切り替え（TODAY / MONTH / TOTAL）に連動して各指標の集計期間が切り替わります。
- 自動更新（UC-2-X1）でHubの最新状態が届いた場合、上部指標も再読み込みなしで即座に更新されます。
- テーブル変更はありません。

### UC-2-X3. ツール別のトークン構成比を表示する

- 主アクター: 利用者。
- 目的: 選択した期間のトークン使用量をツール別に比較し、全体に占める割合を確認します。
- 前提: UC-2-Mによりトップ画面が開かれ、登録Hubの最新保存状態を取得しています。
- 分岐点: UC-2-Mの手順5の後、期間切替時、またはUC-2-X1の更新通知受信時。
- UI確認: 必要。ツール別の数値・構成比、期間切替、使用量がない場合の表示を確認します。
- 実現パターン: 既存のUCP-2を適用します。初回取得と共通更新通知にツール別内訳を含め、共有データから表示します。テーブル変更はありません。

| 手順 | アクター | 操作・処理 |
| --- | --- | --- |
| 1 | アプリケーション | 登録Hubの最新保存状態から、期間別のツール別トークン数を返す |
| 2 | 画面 | 選択期間について、受信済み全Hubの同じツールのトークン数を合算する |
| 3 | 画面 | 各ツールのトークン数を全ツールの合計で割り、構成比を算出する |
| 4 | 画面 | ツール欄に、使用量順の一覧と構成比の棒グラフを表示する |
| 5 | 利用者 | TODAY・MONTH・TOTALを切り替える |
| 6 | 画面 | 選択された期間で集計し直し、表示を更新する |
| 7 | 画面 | UC-2-X1の更新通知を受けるたびに、選択期間を維持して表示を更新する |

受け入れ条件:

- ツール欄の固定サンプルを保存データに置き換え、この欄の「固定サンプル」表示を削除します。
- 「最も利用したツール」およびその専用表示は設けません。
- 集計元は各Hubの `stats.periods.today / month / allTime` にある `clients` とします。同じツール識別子をHub間で合算し、デバイス別の値は重ねて加算しません。未受信Hubは集計に含めません。
- 構成比の分母は、選択期間の全ツールのトークン数合計とします。
- 各ツールの名前、カンマ区切りの整数のトークン数、小数第1位までの構成比、構成比に比例した棒を表示します。割合は個別に丸めるため、表示上の合計が100%にならない場合があります。
- ツールはトークン数の降順で全件表示し、「その他」への集約は行いません。同数の場合はツール識別子の昇順とします。
- 受信済みHubがない場合は「まだ情報を受信していません」と表示します。受信済みで全ツールの合計が0の場合は「この期間のトークン使用量はありません」と表示します。
- 期間切替と自動更新に連動します。通知接続の切断中は最後の表示を保持し、再接続後に最新値へ更新します。
- 初回取得失敗時はツール欄にも取得失敗を表示し、使用量0や固定サンプルで代替しません。
- 今回の対象はツール別トークン構成比です。ツール別コストなど他パーツの実データ化は含めません。モデル欄はUC-2-X4で扱います。

### UC-2-X4. モデルトークン構成比を表示する

- 主アクター: 利用者。
- 目的: ダッシュボードの「モデル」欄に、全Hubの受信情報に基づくモデル別のトークン消費量と構成比を表示します。
- 前提: UC-2-Mによりトップ画面が開かれ、Hub情報が取得されている。
- 分岐点: UC-2-Mの手順5の後、またはUC-2-X1の更新通知受信時。
- UI確認: 必要。モデル欄の実データ反映、モデル別トークン数と構成比バーの描画、期間切り替え（TODAY / MONTH / TOTAL）への連動、更新通知時の自動反映、未受信時・利用データなし時の表示を確認します。

| 手順 | アクター | 操作・処理 |
| --- | --- | --- |
| 1 | 画面 | 共有データ（全Hubの最新状態）から、選択中期間の全Hubのモデル別トークン数を集計する |
| 2 | 画面 | 各モデルのトークン数と全モデル合計に対する構成比（%）を算出する |
| 3 | 画面 | 「モデル」欄へモデル別のトークン数と構成比バーを降順で表示し、「固定サンプル」バッジを削除する |
| 4 | 利用者 | 期間（TODAY / MONTH / TOTAL）を切り替える |
| 5 | 画面 | 選択された期間に合わせて、モデル別トークン数と構成比を再集計して表示を更新する |
| 6 | 画面 | UC-2-X1によるデータ更新を受信した際、手順1〜3を自動で再実行する |

受け入れ条件:

- ダッシュボードの「モデル」パネルが固定サンプルから保存データに基づく値に置き換わり、「固定サンプル」バッジが削除されます（実データ反映済みの箇所はバッジなし）。
- 集計対象は、受信済み全Hubの選択中期間（TODAY・MONTH・TOTAL）におけるモデル別トークン数（`models`）とし、全Hub合算で集計します。
- モデル一覧はトークン数の降順で並べ、各行にモデル名、トークン数（カンマ区切り整数）、構成比（%）、および構成比に対応するプログレスバーを表示します。
- トークン数の多い上位9モデルを表示し、10件目以降は「その他」として合算して10行目に中立色で表示します（その他を含めて最大10件。モデル総数が9件以下の場合は全件表示し、「その他」は表示しません）。
- 受信済みHubが存在しない、または選択中期間のモデル別トークン合計が0の場合は、「利用データがありません」と表示し、固定サンプルは表示しません。
- 期間切り替え（TODAY / MONTH / TOTAL）に連動して各モデルの集計値および構成比が切り替わります。
- 自動更新（UC-2-X1）でHubの最新状態が届いた場合、モデル構成比も再読み込みなしで即座に更新されます。
- テーブル変更はありません（既存の `hub_states.stats_json` 内の `periods[period].models` を利用）。

### UC-2-X5. 利用枠を表示する

- 主アクター: 利用者。
- 目的: ダッシュボードの利用枠欄で、登録Hubの保存済み利用枠の残量を確認します。
- 前提: UC-2-Mによりトップ画面が開かれ、Hub情報が取得されている。
- 分岐点: UC-2-Mの手順5の後、またはUC-2-X1の更新通知受信時。
- UI確認: 必要。利用枠欄の実データ反映、残量の色、未受信・取得失敗時の表示、期間切替で値が変わらないこと、自動更新時の反映を確認します。

| 手順 | アクター | 操作・処理 |
| --- | --- | --- |
| 1 | 画面 | 共有データ（全Hubの最新状態）から、表示対象の利用枠行を集める |
| 2 | 画面 | 同一アカウントの同一枠が複数Hubにある場合は1行にまとめ、メーター残量が最後に変わったアカウントを先に、そのアカウント内では時間幅の狭い window の順に並べる |
| 3 | 画面 | 利用枠欄へ名称・残量パーセント・残量バー・枠の種別・リセットまでの時間を表示する |
| 4 | 利用者 | 期間（TODAY / MONTH / TOTAL）を切り替える |
| 5 | 画面 | 期間切替では利用枠の値を変えず、手順3の表示を維持する |
| 6 | 画面 | UC-2-X1によるデータ更新を受信した際、手順1〜3を自動で再実行する |

受け入れ条件:

- 画面2段目の「利用枠」欄が固定サンプルから保存データに基づく値に置き換わります。この欄の「固定サンプル」ラベルは削除します。未更新のパーツ（トレンド、アクティビティ）にのみ「固定サンプル」を残します。
- 表示対象は、受信済みHubの Hub 集約 `limits.providers` のうち、`showMeter` が真で `remainingPercent` が数値の window です。未設定・未認証などで window が空の provider は出しません。デバイス個別の `limits` は使いません。
- 複数Hubに同じ枠がある場合は、`provider`・`accountKey`・`kind`・`limitId`（無い場合は `label`）が一致する行を1つにまとめ、メーター残量が後から変わった方を残します。Hub名は行に出しません。
- 表示はアカウント単位（`provider` + `accountKey`）でまとめます。例: Codex Plus の 5時間枠と週次枠は連続して出します。アカウントの並びは、そのアカウントの表示対象 window のうちメーター（`remainingPercent` / `usedPercent`）が最後に変わった時刻が新しい順です。鮮度通知の `limits.updatedAt` と受信時刻は使いません。同一アカウント内は時間幅の狭い window を先にします。時間幅は `windowMinutes` があればその値、無ければ kind（session → daily → weekly → billing）に対応する幅です。
- アカウント名はアカウントごとに1回だけ出します。名称は provider を先頭大文字にした表示名で、同一 provider にアカウントが複数ある場合のみ `accountLabel` または `planLabel` を足します。各 window 行の左は `label` が空でなければその値、空なら kind（`session` / `daily` / `weekly` / `billing` を先頭大文字）です。
- 残量は `remainingPercent` を四捨五入した整数パーセントで表示し、バーの長さも残量に合わせます。残量20%未満は注意色、10%未満は危険色です。
- `resetsAt` がある行は、画面表示時点のローカル時刻からの差分を「リセットまで X日Y時間」「リセットまで Y時間」「リセットまで Z分」のいずれかで、残量パーセントの左へ少し離して同じ行に左寄せで出します。差分が負の場合は「リセット予定を過ぎています」とします。`resetsAt` が無い行はリセット文言を出しません。
- 受信済みHubが0件の場合は「まだ情報を受信していません」と表示します。受信済みでも表示対象の枠が0件の場合は「表示できる利用枠はありません」と表示します。
- 初回取得に失敗した場合は、利用枠欄に「利用枠を取得できませんでした」と表示します。保存済みデータと接続設定は変更しません。
- 期間切替（TODAY / MONTH / TOTAL）では利用枠の値を変えません。
- 自動更新（UC-2-X1）でHubの最新状態が届いた場合、利用枠も再読み込みなしで更新します。
- 閲覧用APIと通知はメールアドレスを返しません。接続先URLと認証トークンも返しません。
- テーブル変更はありません。

## 受け入れ条件（主成功系列）

- 現在の接続設定に登録されているすべてのHubを区別して表示し、Hub数を固定しません。
- 過去に設定から外れ、DBだけに残っているHubは表示しません。
- Hub別トークン使用量と推定コストを、日本語の項目名・合計値・構成比の積み上げ棒・色付きの一覧で表示します。構成比はマウスオーバーまたはフォーカスで確認できます。Hub名のすぐ右へ受信デバイスのホスト名を小さく並べます。右端のトークン数・推定コストを優先してホスト名を省略し、マウスオーバーまたはフォーカスで全文を表示します。
- TODAY・MONTH・TOTALは保存済みの `stats.periods.today`・`month`・`allTime` に対応します。Hub欄の数値とグラフを期間に合わせて切り替えます。合計が0の指標は空の棒を表示し、未受信Hubは集計へ加えません。
- 受信済みHub数、登録Hub数、受信済みデバイス数を表示します。未受信Hubはデバイス数へ加えません。
- Hub行には台数・更新日時・Hub間の仕切り線を表示しません。
- Hub欄の数値はSQLiteに保存された最新状態と一致します。
- 画面内のトークン数は、合計・一覧・グラフの目盛りを含め、単位による省略をせずカンマ区切りの整数で表示します。
- 未受信のHubには、Hub名と未受信メッセージを表示します。
- APIは接続先URLや認証トークンを返しません。
- 画面表示によってSQLiteの内容は更新されません。
- 画面を再読み込みすると、その時点でSQLiteに保存されている最新値を表示します。
- 自動更新はUC-2-X1で扱い、手動更新は対象外です。ツール欄・モデル欄・利用枠欄はそれぞれUC-2-X3・UC-2-X4・UC-2-X5で保存データから取得します。アクティビティ、グラフは将来の実装位置を示す固定サンプルで、SQLiteやAPIから取得しません。
- 左ナビと本文のパネル順は、トレンド、Hub・デバイス、ツール、モデル、利用枠、アクティビティで揃えます。左ナビはスクロール位置に追従し、ツール欄とモデル欄は同じランキングバー形式です。
- 補助テキストのコントラスト比は4.5:1以上、最小文字サイズは12pxとします。アクティビティのヒートマップは正方形セルで、月・曜日ラベルと日付ツールチップを表示します。
