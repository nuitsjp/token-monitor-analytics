# Token Monitor Analytics 画面構成

## 1. 文書の位置付け

本書は、[要件定義](requirements.md) に従い、Token Monitor Analytics の画面構成、表示内容、主要操作、画面遷移を定義する。要件定義が唯一の規範仕様であり、本書と要件定義が矛盾する場合は要件定義を正とする。[デザインシステム](design-system.md) は共通の見た目とアクセシビリティ規則、[アーキテクチャ設計](architecture.md) は実装責務を定義する従属文書である。

本書は Phase 1 と Phase 2 を完了した製品の画面構成を示す。各画面または機能には、実装対象を次のように記す。

- **Phase 1**: 収集、識別・関連付け、利用上限推定、履歴、パージ、バックアップ、復元
- **Phase 2**: 利用実績分析、標準価格との比較、可視化、CSV・JSON エクスポート
- **共通**: 両 Phase で使用する画面枠、状態表示、遷移

PoC の月次ダッシュボード、単一点式の簡易推定、クラウド同期画面は目標仕様ではないため、本書へ引き継がない。

## 2. 画面設計の目的

利用者が行う主要な判断と、判断に使用する画面を次に示す。

| ユースケース | 利用者が判断・実行すること | 主な画面 |
| --- | --- | --- |
| 日常確認 | 今日と今月にどれだけ利用したか、最近利用した利用枠がどれだけ残っているかを短時間で確認する | T01 コンパクトトップ |
| 収集運用 | Hub が正常に収集できているかを確認し、接続確認、手動収集、開始・停止を行う | M01 概要、M07 Hub・収集 |
| 確認作業 | 未同定、未関連付け、不整合、完全性未確認など、推定を妨げる項目を根拠付きで解決する | M04 要確認、M05 アカウント・関連付け、M06 サービス・プラン |
| 推定確認 | 利用上限が算出できたか、品質状態と未算出理由は何か、どの観測が根拠かを確認する | M03 利用上限・価値、M08 観測と根拠 |
| 利用分析 | 指定期間のトークン数、API 換算利用額、モデル内訳、共有利用実績を分析する | M02 利用実績 |
| 価値確認 | 利用枠ごとの月間換算推定利用上限と標準価格推定最大価値倍率を確認する | M03 利用上限・価値、M06 サービス・プラン |
| データ保全 | 容量を確認し、バックアップ、復元、明示パージを安全に実行する | M09 データ管理 |
| 追跡 | 設定変更や推定結果から、変更前後、元観測、原 JSON、計算論理版へ遡る | M08 観測と根拠、M10 監査記録 |

## 3. 画面設計の原則

### 3.1 常駐表示と詳細操作を分離する

次のウィンドウ分離と単一起動は、要件を満たすために本書で採用する画面設計上の前提である。

- 起動時から表示する T01 コンパクトトップは、日常確認に必要な値と状態だけを一列で表示する。
- 編集、詳細分析、根拠確認、破壊的操作は、T01 から別ウィンドウとして開く横長のメイン画面へ集約する。
- メイン画面は一つだけ起動する。T01 から再度開く場合は、既存のメイン画面を前面へ移動し、指定された画面へ遷移する。
- メイン画面を閉じても T01 は閉じず、常に最前面へ表示する。

### 3.2 値の性質を混同しない

- 単一論理アカウントに帰属する利用実績、共有利用実績、共有観測利用額、推定アカウント寄与額、ユーザーの設定値を、名称、バッジ、凡例で区別する。色だけで区別しない。
- 共有利用実績と共有観測利用額は全体へ一度だけ含め、根拠なく論理アカウント別へ按分しない。
- 推定アカウント寄与額には常に `推定` と表示し、Hub が観測したアカウント別利用額として表示しない。
- API 換算利用額を実際の請求額として表示しない。
- 月間換算推定利用上限を当月利用額または請求額として表示しない。
- 残高、クレジット、従量額、絶対量をパーセントへ変換しない。

### 3.3 不明な値を補わない

- 各指標の成立に必要な観測、API 契約、関連付け、完全性、プラン、倍率のいずれかが不足する場合、その指標だけを `—` とし、状態理由を表示する。未関連付けの観測や共有利用実績も集計できる全体利用実績まで非表示にはしない。
- 補間、外挿、平均、均等配分、推測による関連付けを行わない。
- 古い値を現在値に見せない。観測時刻または根拠観測時刻と、その経過時間を併記する。

### 3.4 根拠へ遡れるようにする

集計値または推定結果から、次の順にドリルダウンできるようにする。

```text
集計値・推定結果
  └─ 計算区間または集計内訳
      └─ 差分行・推定観測点
          └─ 対応観測
              └─ 元観測
                  └─ 取得元 Hub・観測ソース・JSON パス
                      └─ 原 JSON スナップショット
```

## 4. ウィンドウ構成

| ID | ウィンドウ | 形態 | 役割 |
| --- | --- | --- | --- |
| T01 | コンパクトトップ | 常に最前面の小型ウィンドウ | 日常的な利用量、残り（%）、収集状態、要確認件数の確認 |
| M00 | メイン画面枠 | 通常の横長ウィンドウ | 左メニューと各詳細画面を格納する共通枠 |

### 4.1 T01 コンパクトトップ

T01 は幅 360 DIP（デバイス非依存ピクセル）の一列構成とする。既定の折りたたみ表示では、主要指標と利用増加を最近確認した利用枠を最大 2 件表示する。利用増加を証明できる系列がない場合は、関連付け済みの最新 canonical 利用枠観測を、推定値や増加時刻と区別して同じ件数まで表示する。利用者が展開した場合だけ幅を 420 DIP とし、利用枠を最大 4 件表示する。高さは現在のモニターの作業領域の 50% を上限とし、上限を超える場合は利用枠一覧だけを縦スクロールする。左メニュー、詳細表、編集フォームは配置しない。

T01 はアプリ実行中に最前面表示を維持し、最小化操作を提供しない。タイトル領域から移動でき、画面端へ吸着できるようにする。M00 を開いたときは、可能な範囲で M00 と重ならない画面端へ配置する。定期更新では T01 をアクティブ化せず、他のアプリケーションからキーボードフォーカスを奪わない。

T01 の位置、展開状態、表示していたモニターを保存する。起動時、モニター切断時、解像度または DPI 変更時は、現在利用できるモニターの作業領域内へ必ず戻し、文字や操作部を切り取らず再レイアウトする。T01 の終了操作は、定期収集も停止することを確認したうえで M00 とアプリ全体を終了する。M00 の終了は M00 だけを閉じる。タスクトレイへ隠れて収集を継続する動作は提供しない。

### 4.2 M00 メイン画面枠

既定サイズを 1280 × 800 DIP、最小サイズを 1024 × 640 DIP とする、横長でリサイズ可能なウィンドウとする。作業領域が最小サイズより小さい場合は作業領域全体へ収め、左メニューを維持したまま本文をリフローまたはスクロールし、操作部を画面外へ切り取らない。左メニューの既定幅は 224 DIP とする。モバイル向け構成は対象外とする。

M00 の位置、サイズ、最大化状態、表示していたモニターを保存する。起動時またはモニター切断時に保存位置が利用できない場合は、T01 と同じモニターの作業領域内へ戻す。T01 と M00 はタスクバーと Alt+Tab に別ウィンドウとして表示し、Alt+Space の標準システムメニューを使用できるようにする。Alt+F4 は、T01 ではアプリ全体終了の確認、M00 では M00 だけの終了として扱う。

│                      ├──────────────────────────────────┤

- 左メニューは常時表示し、大分類、画面名、状態件数を表示する。
- 画面上部には、パンくず、画面名、画面固有の主要操作を置く。
- M04～M07 は左側の一覧と右側の詳細ペインを同時表示する。M02 と M03 はグラフ・表を全幅表示し、選択対象を詳細ページへ開く。M08 と M10 は全幅のページング一覧から詳細ページへ開く。M09 は全幅のタブ画面とする。
- 根拠確認の深い階層ではパンくずを維持し、元の絞り込みと選択行へ戻れるようにする。
- M04 のメニューバッジは未解決の要確認作業件数、現在有効なデータ警告件数、判断保存後の再計算失敗件数を分ける。M07 は接続異常、最終取得失敗、未対応契約の件数を表示し、意図的な無効化・停止は異常件数へ含めない。
- 一覧が長期的に増加する M04～M08、M10 には検索、状態絞り込み、並べ替え、ページングまたは仮想化を設ける。ページを移動しても絞り込みと選択状態を維持する。

## 6. T01 コンパクトトップ

### 6.1 表示内容

#### ヘッダー（Phase 1）

- 接続状態、定期収集の有効・停止、現在の実行状態、最終取得結果を別の項目として扱う。一つの総合状態へ畳み込まない。
- コンパクト表示には、`定期収集が有効な Hub 数 / 有効 Hub 数`、現在実行中の件数、異常な Hub 件数を表示する。複数 Hub の結果を一つの `最終結果` に代表させない。
- 有効な Hub の最新取得結果が失敗の場合だけ `取得エラー N Hub` を表示する。後続の取得が成功したら非表示にし、過去の失敗は取得履歴に残す。失敗回数と失敗中の Hub 数を混同しない。
- 詳細表示には、Hub ごとの接続確認結果、定期収集状態、現在の実行状態、最終成功、最終失敗、重複要求による最終スキップを別々に表示する。
- 意図的に無効化または停止した Hub を接続異常として数えない。到達不能、TLS エラー、認証失敗、未対応 API 契約などはヘッダーの Hub 異常件数へ数える。
- 状態を選択すると M07 Hub・収集を開く。
- `詳細` を選択すると M01 概要を開く。

#### 当日・当月のトークン総使用量（Phase 2）

- 当日のトークン総使用量と、当月のトークン総使用量を `取得済み観測の合計` と明記して並べて表示する。Hub が取得していない利用を含む完全なサービス利用量とは表現しない。
- M02 利用実績と同じ重複排除済み集計結果を使用し、共有利用実績も全体へ一度だけ含める。
- 既定の `全体` は、対象期間に保存されている全登録 Hub の観測を対象とする。現在無効な Hub の過去観測も対象期間内であれば含める。
- 推定アカウント寄与額をトークン総使用量へ混ぜない。
- 当日と当月の境界は、M11 で選択した表示タイムゾーンに従う。集計実行時刻、対象 Hub 数、対象 Hub ごとの最終成功時刻の最小・最大、対象期間に観測がない Hub 数をカード直下に表示する。集計実行時刻を観測時刻として扱わない。表示タイムゾーン名はこのカードへ常時表示しない。
- 各カードの鮮度表示から、対象期間の取得履歴で絞り込んだ M07 へ遷移できるようにする。Hub ごとの最終成功時刻が大きく異なる場合も、単一の代表時刻へ置き換えない。
- 取得元タイムゾーンが不明な取得元ローカル日付の集計値は、選択した表示タイムゾーンの日・月へ再配分しない。該当データがある場合は `集計対象外あり` を表示し、M02 の取得元ローカル日付内訳へ遷移できるようにする。
- 対象期間内に記録済みの取得失敗がある場合は `取得失敗あり`、重複要求によるスキップがある場合は `重複要求スキップあり` と別々に表示し、M02 から取得履歴へ遷移できるようにする。重複要求のスキップだけを取得失敗または Hub 異常として扱わない。記録されていない収集予定やアプリ停止中の欠損を推測して `一部データ` と判定しない。
- 当日のカードを選択すると、M02 を当日、全体、トークン数で開く。当月のカードは当月で開く。
- Phase 1 では二つのトークンカードをセクションごと隠し、無効なカードや空の場所を残さない。

#### 利用増加を最近確認した利用枠（Phase 1）

- 現在有効な論理アカウントと、確認済みの利用枠定義に属する、有効なパーセント型利用枠を、既定では最大 2 件、展開時は最大 4 件表示する。アーカイブ済み論理アカウントの新規観測は表示せず、M04 の要確認へ表示する。
- 「利用増加を最近確認した」は、同じアカウント利用枠系列かつ同じ利用周期にある隣接した有効観測で、`usedPercent` の増加を最後に観測した時刻が新しい順とする。任意の日数で自動除外せず、利用増加を確認した時刻と経過時間を常に表示する。
- リセット、観測系列の断絶、未確認の名称変更境界をまたいで利用発生を推測しない。増加を確認できない系列は表示対象にしない。
- 各行には、サービス、論理アカウント、利用枠定義、残り（%）、リセット日時、利用増加を最後に確認した時刻、最新の利用枠観測時刻と、それぞれの経過時間を表示する。二つの時刻を一つの `観測` 表示へまとめない。
- 残り（%）は、Go の表示 DTO が返す `remainingPercent` を使用し、通常画面では小数第 1 位まで表示する。元観測値ではないことと、詳細画面・Tooltip・出力では小数第 2 位まで表示することを示す。UI は `usedPercent` から再計算しない。
- リセット日時がない場合は `不明`、最新観測より後の観測がないままリセット日時を過ぎた場合は `経過済み` と表示し、次のリセットを推測しない。
- 複数の利用枠は別々に表示し、残り（%）や推定上限を合計しない。
- 行を選択すると M03 を対象の論理アカウントと利用枠定義で開く。

#### フッター（Phase 1）

- 操作で解決できる未確認項目、現在有効なデータ警告、判断保存後の再計算失敗を別々に数え、選択すると M04 の該当状態を開く。
- プライバシーモードでは、論理アカウント名、正確なトークン数、残り（%）、リセット日時などの機微値を共通のマスク規則で伏せ、収集状態と異常件数だけを表示する。T01 の操作または `Ctrl+Shift+P` で切り替え、visible text、Tooltip、`title`、`aria-label`、アクセシブル説明、クリップボード、タスクバーのサムネイルにも同じマスク結果を適用する。

## 7. メイン画面

### 7.1 M01 概要（Phase 1 / 2）

メイン画面を詳細指定なしで開いたときの初期画面とする。

初回設定が完了していない間は、通常の概要カードより前に次のチェックリストを表示する。各項目に未着手、進行中、完了、要対応を表示し、現在実行できる次の一項目へ直接遷移できるようにする。

1. OS のタイムゾーンを候補として表示し、M11 で表示タイムゾーンを明示確認する

7. M03 で推定状態と、残っている未算出理由を確認する

**Phase 1 の表示**

- Hub の接続状態、定期収集状態、現在の実行状態、最終取得結果を別々に集計した件数と最終成功時刻
- 要確認作業、現在有効なデータ警告、判断保存後の再計算失敗の種類別件数
- M03 に表示する全アカウント利用枠系列の推定状態別件数
- 非カレントの最新有効計算区間を表示している対象の件数
- データベースのファイルサイズ、原 JSON スナップショット件数、最古・最新取得日時
- 直近のバックアップ作成結果と、最新の復元試験合格日時を別々に表示し、資格情報は成果物に含まれない旨
- 各カードから M03、M04、M07、M09 への遷移

**Phase 2 で追加する表示**

- 当日・当月のトークン総使用量と API 換算利用額
- 共有利用実績の内訳
- 最近の利用実績と、利用上限・価値の要約
- M02 と M03 へのドリルダウン

### 7.2 M02 利用実績（Phase 2）

#### 絞り込み

- 期間、集計粒度、積み上げの分類を期間指定箇所に表示する。詳細指定なしで開いた場合は、選択中の表示タイムゾーンにおける当月開始から現在まで、日単位、モデル分類を初期値とする
- 期間指定箇所に表示タイムゾーンの現在値を示す。この画面では変更せず、変更は M11 で行う
- Hub
- 収集端末
- Hub 端末レコード
- サービス
- 生利用額サービス識別子
- 論理アカウント
- プラン版
- 利用枠定義
- モデル

Hub 以降の分類条件は `詳細フィルター` にまとめ、折りたたみ可能とする。適用中の条件は折りたたみ時もチップと件数で表示し、一括解除できるようにする。初期状態の Hub は `全登録 Hub` とし、現在無効な Hub の対象期間内の過去観測も含める。有効 Hub だけへ絞り込む場合は、利用者が明示的にフィルターを変更する。

#### 表示

- トークン数、API 換算利用額、モデル別内訳のサマリー
- 残高、クレジット、従量額、通貨を元の単位のまま表示する独立した表
- 同じ時間軸上で、トークン利用量を左軸、API 換算利用金額を右軸とし、選択した分類の内訳をそれぞれ積み上げる並列棒グラフ。分類キー、並び順、色は両方の棒で共通とする
- 積み上げの分類は、モデル、契約（観測時点で有効なプラン版）、AI エージェント（Hub の `clients` に記録された観測クライアント識別子）のほか、Hub、収集端末、Hub 端末レコード、正式サービス、生利用額サービス識別子、論理アカウントへ切り替えられる。AI エージェント名は観測識別子から推測しない
- 期間合計に占めるトークン利用量と API 換算利用金額の寄与率を同じ重みで評価し、上位5分類を個別に表示する。6位以下は灰色の `それ以外` へ集約し、全期間の棒で同じ分類集合を使用する
- 日次、週次、月次を切り替え、任意期間の各棒から該当期間の分類別内訳へ切り替えられる操作
- グラフと同じ期間、分類、帰属、トークン利用量、API 換算利用金額、差分数を確認できる時系列表
- 全体、Hub、収集端末、Hub 端末レコード、サービス、生利用額サービス識別子、論理アカウント、契約、AI エージェント、モデルごとの期間合計内訳表
- 単一論理アカウントへ完全に帰属できる観測実績
- 複数論理アカウントに関係する共有利用実績と共有観測利用額
- 表示する場合は別系列とした推定アカウント寄与額
- 取得元タイムゾーンが不明な日次・月次値を、取得元ローカル日付のまま示す別表

グラフと表の系列名は、`単一アカウントに帰属する利用実績`、`共有利用実績`、API 換算利用額の場合の `共有観測利用額`、`推定アカウント寄与額（推定）` を明記する。同じ分類の共有利用実績は分類色を変えず、斜線と系列名で帰属を区別する。利用額の累積値差分は同じ利用額ソースの隣接する有効観測だけを使用し、リセット、Hub 切替、観測系列の断絶をまたがない。`session` や推定対象外の利用枠に対応する利用も、利用額ソースで観測されたトークン数と API 換算利用額には含める。

同じ元観測または利用額ソースは全体へ一度だけ含めるが、別 Hub の観測を内容や値の一致だけで重複排除しない。

論理アカウント、プラン版、利用枠定義で絞り込んだ場合は、対象期間に有効なプラン履歴と関連付けを用いて行を選び、単一論理アカウントへ完全に帰属する実績と、選択対象に関係する共有利用実績を別のサマリーへ表示する。共有利用実績は全額を一度だけ表示し、複数の選択対象に関係しても繰り返さない。単一アカウントの合計には加えず、選択対象への配分額も算出しない。

#### 利用実績の操作

- 集計値または内訳行から M08 の使用元観測へ遷移する。
- 各グラフと内訳表の見出しに出力操作を置き、現在選択している一つの表示系列または内訳表を一つの成果物として出力する。グラフは表示中の集計粒度のデータ点、表は現在の絞り込みに一致する全行を対象とし、ページング中の一ページだけに限定しない。
- 現在の絞り込み、単位、表示タイムゾーン、集計期間、観測・推定区分、スキーマ版、生成 UTC 日時を、CSV または JSON の成果物自体へ含めて出力する。
- CSV と JSON の出力操作は同じメニューへまとめ、形式を選択して実行する。
- CSV は UTF-8 BOM 付きの RFC 4180 形式、JSON は UTF-8 でトップレベルに `schemaVersion`、`metadata`、`rows` を持つことを出力確認に表示する。
- 出力確認には、保存先、対象系列または表、全行数、出力列、スキーマ版、生成 UTC 日時、アカウント識別情報と利用履歴を含み得る機微データであることも表示する。
- 出力は M00 を操作不能にせずバックグラウンドで実行し、進捗、保存先、キャンセル、成功、失敗を表示する。キャンセルまたは失敗時は未完成の成果物を残さない。

### 7.3 M03 利用上限・価値（Phase 1 / 2）

#### 利用上限・価値の一覧

一覧の起点は、現在有効な `論理アカウント × 利用枠定義` のアカウント利用枠系列とする。計算対象集合を形成できない系列も一覧から除外しない。サービス、状態、プラン版、利用枠定義で絞り込み、状態、残り（%）、最新観測時刻で並べ替えられるグループ化表として表示する。

各行には次を表示する。

- サービス、論理アカウント、利用枠定義、周期種別
- 適用中のプラン版
- 推定状態と状態理由
- 最新の利用率、残り（%）、リセット日時、利用枠観測時刻
- 系列の正常、不整合、断絶の状態
- 計算対象集合を形成できる場合は、その集合と適用されるプラン利用上限への参照

計算対象集合を形成できる行は集合単位でまとめ、グループ見出しに `プラン版 × 利用枠定義` ごとの次の値を一度だけ表示する。

- カレント計算区間の期間
- プラン利用上限（API 換算）
- 推定済みの状態バッジ
- 同じプラン版と利用枠定義にある非カレントの最新有効計算区間を参照している場合、その旨、根拠観測時刻、経過時間。プラン版の境界を越えて参照しない
- Phase 2 の月間換算推定利用上限、USD 建て月額標準シート単価、標準価格推定最大価値倍率

状態は次の順序で一つに決める。

1. 利用枠の種別または単位が推定対象でなければ `推定対象外`
2. 対応 API 契約、関連付け、完全性、プランまたは倍率などの前提が不足していれば `未算出`
3. 前提がそろい、推定観測点または差分行が不足していれば `観測不足`
4. 行数は足りるが独立性または利用額の信号が不足していれば `識別不能`
5. 観測数と階数は足りるが有限かつ正の解を得られなければ `モデル不適合`
6. 必要十分な観測と有効な差分から有限かつ正の一意解を得た場合は `推定済み`

同じプラン版を参照する複数アカウントについて、プラン利用上限をアカウント固有の値として繰り返さない。複数の利用枠のプラン利用上限や価値倍率は合計しない。

#### 詳細

1. **現在**: アカウント利用枠系列、推定適格性、前提充足状態を表示する。計算対象集合を形成できる場合は、カレント計算区間の期間、状態、状態理由、プラン利用上限も表示する。
2. **利用枠系列**: アカウント利用枠系列を構成する利用枠ソース、確認済み名称変更、利用率、リセット日時、同時刻不整合、系列の断絶を表示する。
3. **品質**: 観測点数、差分行数、階数、最大時刻差、計算論理版を表示する。
4. **履歴**: 計算区間ごとの結果、利用周期、開始・終了境界の種別と発生日時を時系列で表示し、境界の根拠イベントへ遷移できるようにする。カレントと非カレントを区別し、最新有効計算区間という参照上の役割は別のバッジで示す。値の年齢だけで自動失効させない。
5. **価値**: Phase 2 の月間換算式、使用した標準シート単価、その出典 URL と有効期間、プラン利用上限と価値倍率の推移を表示する。
6. **根拠**: 差分行、推定観測点、対応観測、元観測、利用額ソース、関連付け、完全性確認、プラン履歴を表示する。異なるプラン版を同じ方程式系で扱った場合は、適用した基準プラン、利用上限倍率、公式根拠 URL、有効期間も表示する。

根拠の各行から M08 の対応観測、元観測、原 JSON へ順に遷移できるようにする。モデル不適合で保持した候補値は監査用の詳細だけに表示し、一覧の主要指標や価値計算へ使用しない。有効な標準シート単価がない場合も Phase 1 の推定値を表示し、価値倍率だけを `—` と理由付きで表示する。

Phase 2 の推移グラフは、計算区間ごとのプラン利用上限（推定）と標準価格推定最大価値倍率を別系列で表示し、各点に推定済みの状態を示す。観測値の系列名を使用せず、モデル不適合の候補値を通常系列へ含めない。

推移グラフと履歴表の見出しに CSV・JSON 出力操作を置く。現在の対象、期間、単位、表示タイムゾーン、推定区分、スキーマ版、生成 UTC 日時を成果物へ含め、形式、機微データ、保存先、全行数、出力列を実行前に確認する。形式と実行状態は M02 と同じ規則に従う。

### 7.4 M04 要確認（Phase 1）

操作で解決できる項目と、元観測を書き換えずに確認する警告を分ける。M04 は作業キューと根拠確認を担い、設定値の正本を直接編集しない。判断操作を選択した場合は、対象、根拠、戻り先を維持して M05 または M06 の該当編集画面へ遷移する。保存後は M04 の同じ絞り込みへ戻り、次の未処理項目を選択する。

#### 要確認作業タブ

- 未確認のサービス・プラン同定候補
- Hub アカウントの論理アカウント作成・統合候補
- 未関連付けの利用額ソースのうち、同じ Hub 端末レコードとサービスに利用枠観測があり、アカウント関連付けを判断できるもの
- 未関連付けの利用枠ソース
- 利用枠名称変更候補
- 利用者が登録した、月次利用枠であることを未確認の `billing` ウィンドウ。自動観測した未確認ウィンドウは推定対象外として保持するが、要確認件数へ含めない
- Hub 切替に必要な旧・新 Hub 端末レコード、収集端末、切替日時の未確認項目
- 空でない Hub 報告プランとプラン履歴の不整合、または正確なプラン変更時刻が不明な区間。報告プラン名自体が空の場合は不整合とみなさない
- アーカイブ後の新規観測
- 利用額ソース区間の活動主体の完全性未確認

一覧には、種類、状態、対象、取得元 Hub、対象期間、最初・最後の観測時刻、推定への影響を表示する。サービス・プラン同定候補では、生利用枠サービス識別子と生報告プラン名の原形文字列を別項目として必ず表示する。一覧行を選ぶと右側に根拠観測、非秘密の Hub アカウント表示情報、現在の関連付け、判断操作を表示する。

| 種類 | 判断操作 |
| --- | --- |
| サービス・プラン同定候補 | M06 でサービスとプランへの対応を確認、対象外、確認解除 |
| Hub アカウント候補 | M05 で論理アカウントを作成、既存論理アカウントへ関連付け、分割・統合 |
| 未関連付けの観測ソース | M05 で対象と有効期間を指定して利用額関連付けまたは利用枠関連付けを作成 |
| 利用枠名称変更候補 | M05 で同じ利用枠、別の利用枠、未確認のまま保留のいずれかを選択 |
| `billing` ウィンドウ | M06 で月次利用枠であることを確認 |
| Hub 切替 | M05 で収集端末、旧・新 Hub 端末レコード、切替日時を確認 |
| プラン不整合 | M05 でプラン履歴と正確な変更時刻を修正 |
| アーカイブ後の新規観測 | M05 でアーカイブ解除、別の論理アカウントとして扱う |
| 活動主体の完全性 | M05 で区間内の全論理アカウントと除外対象がないことを確認 |

変更を確定する前に、遷移先の編集画面で影響する計算区間と再計算対象を表示する。一括確定は提供せず、一件ごとに根拠を確認して処理する。T01 と左メニューの `要確認` 件数は、利用者の判断がまだ保存されていない項目だけを数える。

判断状態と再計算状態を分けて保持する。必要な判断が監査履歴付きで保存された時点で `判断済み` とし、未解決件数から除く。影響区間の再計算は `待機中`、`実行中`、`完了`、`失敗` を表示する。再計算に失敗しても判断を未確認へ戻さず、`判断済み・再計算失敗` として失敗理由、再試行、M08 の計算根拠への導線を表示する。T01 と左メニューの `処理失敗` 件数には、この状態を数える。

#### データ警告タブ

- `accountKey` が欠落または空の未同定 provider 行
- 利用額観測または利用枠観測の不整合
- 説明できない観測系列の断絶

データ警告は元観測を選び直したり正常として承認したりできない読み取り専用表示とする。取得元、該当する全観測、JSON パス、推定から除外された理由、関連する設定画面への導線を表示する。設定の修正または後続観測によって状態が変わった場合だけ、再計算結果へ反映する。

同じ `Hub × 観測ソース × 警告種別` の継続発生は一つの警告事象としてまとめ、最初・最後の観測時刻と発生回数を表示する。後続の有効観測または設定変更で解消された事象を履歴へ移す。T01 と左メニューの `警告` 件数には、計算区間を形成できない警告も含め、現在有効な警告事象を一件ずつ数える。各事象には `カレント計算へ影響`、`計算区間形成不能`、`現在影響なし` の影響区分を併記し、過去の解消済み事象は件数へ累積しない。

要確認作業とデータ警告は、種類、状態、影響区分、Hub、期間で絞り込み、最終観測時刻と影響度で並べ替えられるようにする。長期保存する履歴はページングする。

### 7.7 M07 Hub・収集（Phase 1）

#### Hub・収集の一覧

- 表示名
- 不変の Hub 識別子
- URL
- 有効・無効
- 資格情報の登録有無。資格情報そのものは表示しない
- 収集間隔、収集状態、次回予定
- 接続状態
- 最終成功、最終失敗、失敗理由
- 対応 API 契約と、収集・全体利用実績だけに対応するか、利用上限推定にも対応するかの区別

#### Hub・収集の操作

- Hub の登録、表示名・URL・収集間隔の編集、無効化、再有効化
- 資格情報の登録、更新、削除
- 接続確認
- 収集の開始、停止、手動実行
- Hub ごとの取得履歴の表示

Hub が無効な間は、接続確認、定期収集、手動収集を実行できない。再有効化しても定期収集を自動再開せず、利用者が明示的に開始するまで停止を維持する。定期収集だけを停止している Hub では、接続確認と手動収集を実行できる。資格情報未登録または復元後再登録待ちでは、資格情報の登録、Hub 設定の編集、有効・無効の切替以外を実行できない。

新規登録では同じ URL の既存 Hub があっても統合せず、新しい Hub 識別子が発行されることを確認画面に表示する。既存 Hub の URL 編集では Hub 識別子を維持する。Hub の無効化または資格情報の削除は確認後に実行し、保存済みの原 JSON、元観測、関連付け、設定変更監査履歴が残ることを確認画面に表示する。

URL 入力は Hub API の基底 URL とする。`localhost`、ループバック IP、またはプライベート IP のリテラルには HTTP を許可し、それ以外は証明書検証が成功する HTTPS を必須とする。HTTP は共有秘密を平文で送信するため、利用者が管理する信頼済み LAN に限定する。URL の userinfo、query、fragment は保存を拒否し、資格情報を URL へ埋め込ませない。証明書エラーを無視する設定は提供しない。収集間隔は正の値だけを保存できるようにする。

接続結果は、到達不能、タイムアウト、TLS エラー、認証失敗、未対応 API 契約、不正 JSON を区別する。到達不能とタイムアウトには `URL とネットワークを確認` と `再試行`、TLS エラーには非秘密のホスト名と証明書判定、認証失敗には `資格情報を更新`、未対応 API 契約には期待する契約と検出した契約、不正 JSON には取得日時と非秘密の構文判定を表示する。同じ Hub の収集中は手動実行を重ねず、操作を無効にする。収集要求の重複によるスキップも取得履歴に表示する。資格情報、認証ヘッダー、Cookie、原応答本文はエラー詳細へ表示しない。

復元したすべての Hub は、Windows Credential Manager に同じ Hub 識別子の資格情報が残っている場合も一律に `復元後再登録待ち` とする。残存する資格情報を暗黙に再利用せず、利用者が Hub ごとに資格情報を再登録して接続確認が成功するまで収集しない。

### 7.9 M09 データ管理（Phase 1）

バックアップ作成、復元試験、復元検証・適用、明示パージには共通の相互排他制御を設け、同時に一つだけ実行する。いずれかの処理中は、他のデータ管理操作を開始できない。

#### 容量タブ

- ローカルデータベースのファイルサイズ
- 原 JSON スナップショット件数
- 最古・最新の取得完了日時
- 自動削除や任意閾値による警告は提供しない

#### バックアップタブ

- ZIP の保存先選択と手動作成
- 成果物作成は、作成中、検証中、成功、失敗を表示する。
- 復元試験は、未実施、試験中、合格、失敗を成果物作成状態とは別に表示し、最終試験 UTC 日時と対象 SHA-256 を併記する。
- 成果物の作成日時、形式版、スキーマ版、サイズ、SHA-256、検証結果
- 作成した成果物を空の一時データベースへ復元し、主要件数と代表的履歴を照合する `復元試験` 操作と、その結果
- 資格情報を含まないことと、復元後に資格情報の再登録が必要なこと
- 原 JSON、アカウント識別情報、利用履歴を含む未暗号化の機微データであること
- 暗号化された端末外保存先へのコピーが必要であり、アプリは外部転送しないこと
- 同じ端末または同じ媒体だけでは十分な復旧手段にならないこと

#### 復元タブ

1. ZIP を選択する。
2. 形式、版、SHA-256、SQLite 完全性、参照整合性、意味上の制約、秘密データが含まれないこと、正規化データの読み取りと再計算が可能なことを検証する。
3. 検証結果、対象の作成日時、スキーマ版、主要件数、現在のデータベースを置き換えることを表示する。
4. 明示確認後に適用する。
5. 成功時は復元監査記録と、資格情報の再登録が必要な復元済み全 Hub の一覧を表示する。

検証と適用は別の操作とする。ZIP の展開と検証中はキャンセルできるようにし、原子的な入替えの開始後はキャンセルできないことを実行前と処理中に表示する。失敗時は `現在のローカル正本は変更されていません` と理由を表示する。固定の RTO を示さず、RPO は端末外の暗号化保存先へコピーされ、復元試験に合格した最後のバックアップ時点であることを説明する。

復元の適用中は定期収集を停止し、M00 全体を進捗表示でロックする。T01 は数値を現在値として表示せず `復元中` とし、別の収集、編集、パージ、復元、ウィンドウを閉じる操作を受け付けない。成功後は復元したすべての Hub を `復元後再登録待ち` とし、収集を再開しない。失敗後は元のデータベースと適用前の収集状態へ戻す。

起動時に未完了の復元ジャーナルを検出して元のデータベースへ回復した場合は、その結果を M01 の通知とこのタブに表示する。

#### 明示パージタブ

1. Hub 識別子の集合と取得完了日時の半開区間 `[開始, 終了)` を指定する。全 Hub、開始なし、終了なしを明示的に選択できるようにする。
2. 対象 Hub、選択期間、原 JSON スナップショット件数、最古・最新取得日時、保存済み JSON バイト数に基づく論理削減見込みをプレビューする。
3. 原 JSON 全体と、それだけを根拠とする元観測・派生結果が不可逆に削除されることを表示する。
4. Hub、カタログ、論理アカウント、関連付け、プラン履歴、設定変更監査履歴は削除されないことを表示する。
5. 最終確認には Hub の表示名と識別子、絶対日時による対象期間、原 JSON スナップショット件数、削減見込み、不可逆性を再掲する。全 Hub かつ開始なし・終了なしの場合は、表示した確認語句の入力も要求する。
6. 明示確認後に実行し、削除と再計算の両方がコミットされた場合だけ成功件数を表示する。いずれかが失敗した場合はロールバック済みの失敗理由を表示する。

論理削減見込みは、SQLite ファイルが直ちに同じバイト数だけ縮小する保証ではないことを併記する。

パージのプレビュー中はキャンセルできるようにする。削除トランザクションの開始後はキャンセルできないことを実行前と処理中に表示する。削除と残存元観測からの再計算を同じトランザクションで実行し、両方が完了するまで `パージ・再計算中` とする。この間は収集と設定編集を停止し、T01 と M00 の主要指標を現在値として表示しない。トランザクションのコミット後だけ `成功` と新しい主要指標を表示し、失敗時は削除も含めてロールバックした値を再表示する。

### 7.10 M10 監査記録（Phase 1）

- 設定変更監査履歴、パージ記録、復元記録を記録種別として分ける。
- UTC 日時、選択中の表示設定で整形した日時、操作者、操作種別、対象を一覧表示し、設定変更監査履歴には変更前後も表示する。表示タイムゾーン名は常時表示せず、必要な場合だけ詳細で確認できるようにする。
- 関連付け、完全性、候補状態、カタログ、プラン履歴、アカウント分割・統合、パージ、復元で絞り込めるようにする。
- 既定では UTC 日時の降順に表示し、長期保存データはページングして任意の固定件数で切り捨てない。
- 対象の論理アカウント、サービス、観測ソース、復元結果へ遷移できるようにする。
- すべての監査記録は読み取り専用とし、削除操作を提供しない。

### 7.11 M11 表示設定（Phase 1）

- 初回起動時は Windows のタイムゾーンから対応する IANA タイムゾーン識別子を候補として選択するが、保存前に利用者の明示確認を要求する。確認前は T01 と M01 に `表示タイムゾーン未確認` を表示し、当日・当週・当月の集計値を現在値として表示しない。
- IANA タイムゾーン識別子から表示タイムゾーンを選択する。
- 選択中のタイムゾーンによる当日、当週、当月の開始・終了をプレビューする。
- テーマを `light`、`dark`、`system` から選択して保存する。`system` は OS のテーマ変更へ追従し、設定変更と OS 変更を T01 と M00 へ同期する。テーマの現在値は M11 で扱い、他画面へ常時表示しない。
- 暦週は月曜日開始であることを表示する。
- 夏時間による 23 時間日または 25 時間日を一律 24 時間として扱わない旨を説明する。
- 取得元タイムゾーン不明の取得元ローカル日付は、表示タイムゾーンへ再配分されないことを説明する。

### 8.1 状態表示

| 対象 | 必須の状態 |

| 定期収集 | 有効、停止 |
| 現在の収集実行 | 待機中、実行中 |
| 最終取得結果 | 未実行、成功、失敗、重複要求によるスキップ |
| 同定候補 | 未確認、確認済み、対象外 |
| 関連付け | 関連付け済み、未関連付け、期間不整合 |
| 活動主体の完全性 | 確認済み、未確認 |
| 観測系列 | 正常、利用枠観測不整合、利用額観測不整合、観測系列の断絶 |
| 論理アカウント | 有効、アーカイブ済み、アーカイブ後要確認 |
| 推定 | 推定対象外、未算出、観測不足、識別不能、推定済み、モデル不適合 |
| 要確認の判断 | 未確認、判断済み |
| 影響区間の再計算 | 未実行、待機中、実行中、完了、失敗 |
| データ警告 | 現在有効、解消済み。影響区分としてカレント計算へ影響、計算区間形成不能、現在影響なしを併記する |
| 計算区間の時点 | カレント、非カレント |
| 過去区間の参照役割 | 最新有効計算区間。計算区間の時点とは別のバッジで表示する |
| バックアップ作成 | 未実行、作成中、検証中、成功、失敗 |
| 復元試験 | 未実施、試験中、合格、失敗 |
| 復元適用・パージ | 未実行、検証中、処理中、成功、失敗 |

状態コードから日本語ラベル、intent、アイコン、説明、次操作を得る一元マッパーを全画面で使用する。状態はバッジの文字列と説明を併記し、警告色だけで意味を持たせない。推定不能を通信エラーとして表示しない。鮮度状態と理由は Go の表示 DTO をそのまま表示し、UI は経過時間の閾値から独自判定しない。状態の自動更新は、フォーカスを移動せずスクリーンリーダーへ簡潔に通知する。連続する進捗値は読み上げを繰り返さず、開始、完了、失敗、操作可能になった時点を通知する。

### 8.2 数値と単位

- USD は通常画面、詳細画面、Tooltip で小数第 2 位へ四捨五入して表示する。ゲージに併記する割合は通常画面で小数第 1 位、詳細画面・Tooltip・出力で小数第 2 位へ、倍率はすべての表示経路で小数第 2 位へ四捨五入する。
- 保存値、再計算入力、品質判定には表示丸め値を使用しない。CSV・JSON の数値には表示丸めを適用せず、未丸めの保存値または導出値を出力する。
- トークン数、USD、割合、倍率、残高、クレジット、従量額は単位を列名または値に明記する。
- 利用率と残り（%）は同じ行で意味を取り違えないラベルを使用する。

### 8.3 日時と期間

- M02 の期間指定箇所では選択した表示タイムゾーンを表示する。その他の画面ではその設定を使って日時を整形するが、表示タイムゾーン名を常時表示しない。詳細またはツールチップで UTC 瞬時を確認できるようにする。
- 観測時刻と Analytics の取得完了時刻を別の項目として表示する。
- 有効期間は `[開始, 終了)` と画面上に明記する。
- 相対時刻だけでなく絶対日時も確認できるようにする。
- 取得元ローカル日付と表示タイムゾーンによる暦日を同じ列へ混在させない。
- 有効期間を現地時刻で入力したとき、夏時間移行で存在しない時刻は保存を拒否し、二通りの UTC 瞬時に対応する時刻は UTC オフセットを選ばせる。

### 8.4 読込中、空、取得失敗、エラー

- 読込中は値の位置を維持するスケルトンを表示する。直前値を表示する場合は `更新中` と元の観測時刻を併記する。
- `データなし` を一種類にまとめず、Hub 未登録、未取得、指定期間の利用なし、絞り込み結果なし、推定不能を区別する。
- 対象期間に記録済みの取得失敗がある集計は `取得失敗あり`、重複要求によるスキップがある集計は `重複要求スキップあり` と別々に表示する。記録のない収集予定やアプリ停止中の欠損を推測せず、値への影響も断定しない。
- 保存または関連付け変更に失敗した場合は入力内容を保持し、成功したように表示しない。
- パージ失敗時はロールバック済み、復元失敗時は現在データ未変更であることを表示する。
- 自動即時再試行は行わない。認証失敗は資格情報更新、到達不能とタイムアウトは URL・ネットワーク確認と手動再試行、TLS エラーはホスト名と証明書判定の確認、未対応 API 契約は期待契約と検出契約の確認、不正 JSON は取得履歴と非秘密の構文判定の確認を次の操作として示す。
- 論理アカウントがない場合は M05 の登録、サービスがない場合は M06 の登録、元観測がない場合は M07 の手動収集を次の操作として示す。
- 推定対象がない場合は M04 の未確認項目と M06 の利用枠定義を確認する導線を示す。監査記録がない場合は正常な空状態として表示し、作成操作を示さない。

### 8.5 編集と確認

- 一覧の絞り込みと選択状態は、詳細から戻ったときに維持する。
- 関連付け、完全性、候補状態、プラン履歴、カタログ、サービス対応、利用枠定義、基準プラン、プラン版、利用上限倍率、標準価格を変更する前に、対象、有効期間、影響する論理アカウント、計算区間、利用実績集計、価値計算を表示する。
- 保存後は再計算中、完了、失敗を表示する。元観測を変更したように見せない。
- バックアップ作成を除き、復元と明示パージは結果を適用する直前に明示確認する。
- 資格情報入力は伏字とし、保存済みの資格情報を再表示しない。
- 未保存の変更がある状態で、左メニュー、パンくず、T01、詳細の切替、メイン画面の終了から別の表示へ移ろうとした場合は、共通のナビゲーションガードで `保存して移動`、`破棄して移動`、`キャンセル` を表示する。保存失敗時は移動せず入力内容を保持し、キャンセル時は元の画面、絞り込み、選択行、スクロール位置を維持する。
- キーボードだけで、左メニュー、タブ、フィルター、一覧、詳細、パンくず、主要操作、確認ダイアログへ到達し、実行、キャンセル、元の一覧へ戻る操作を完了できるようにする。カードまたは一覧行全体が操作対象の場合も、見えるフォーカスと読み上げ名を付ける。
- モーダルを閉じた後は起点の操作へ、詳細から戻った後は元の一覧行へフォーカスを戻す。T01 から M00 を開いた場合は、遷移先の画面名または引き継いだ対象へフォーカスを移す。
- Windows のハイコントラストで状態、選択、フォーカス、グラフ系列を判別できるようにする。独自 SVG・CSS は `forced-colors`、`currentColor`、システム色を使い、ハードコードした色だけに依存しない。200% の文字拡大でも独自 SVG・CSS を含む情報や操作を欠落させずリフローし、省略した名称はキーボードフォーカスでも全文を確認できるようにする。
- グラフには同じデータを確認できる表を併設し、系列名、単位、観測・推定区分を読み上げ可能なテキストとして持たせる。

### 8.6 機微データと秘密

- 資格情報、アクセストークン、Cookie、認証ヘッダーを画面、エラー詳細、ログ、CSV・JSON エクスポートへ出力しない。
- 原 JSON とバックアップを表示または扱う画面には、アカウント識別情報と利用履歴を含む機微データであることを明示する。
- エラー表示は判定区分と非秘密の診断情報に限定し、認証済み API の応答本文を表示しない。
- T01 のプライバシーモード、原 JSON の表示マスク、CSV・JSON の出力確認は、表示箇所が異なっても同じ機微データ分類と同じマスク規則に従う。visible text、Tooltip、`title`、`aria-label`、アクセシブル説明、クリップボード、タスクバーのサムネイルを例外にしない。

## 10. 対象外

画面へ次の機能を配置しない。

- クラウド複製、クラウドからの復元、複数端末間の設定同期
- 自動バックアップ、バックアップ世代管理、外部保存先への自動転送、アプリ内暗号化
- 請求書、支払い、税、割引、年払い価格、契約固有価格、為替換算の管理
- Hub が取得していない利用データのスクレイピング
- 根拠のない共有利用実績のアカウント別配分
- モバイル向け画面
