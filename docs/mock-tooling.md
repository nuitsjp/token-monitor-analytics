# モック開発ツール (Mock Tooling)

※ 本書の内容は**提案中（未導入）**です。採否と適合性の検証は [U11](../PLAN.md#u11)、選定背景は [ADR 0003](ard/0003-select-mock-tooling.md) を参照してください。

## ツール候補と構成案

設計方針に定める動作確認用 Mock Hub の同梱を前提に、以下の補助ツールを検討しています。

| ツール候補 | 主な用途 | 配置方針 |
| --- | --- | --- |
| Storybook | 本番用 UI コンポーネントおよび各画面状態の単体確認 | 対象コンポーネントと同一ディレクトリ |
| MSW | HTTP/API 応答のインターセプトによるテストデータ再現 | モック定義の正本として一元管理 |
| Playwright | 主要シナリオのエンドツーエンド受け入れテスト | テスト配置方針の確定時に決定 |

※ ブラウザ〜Analytics 間（JSON/SSE）および Analytics〜Hub 間のモック対象境界は [U11](../PLAN.md#u11) で検討します。モック導入のみを目的とした不要な抽象化や通信層の追加は行いません。

## 採用時の運用ルール

- 各 Story、モック定義、テストケースは [機能仕様の重要シナリオ（S1〜S9）](../doc/spec/functional-spec.md#scenarios) の ID と対応付けて管理する。
- HTTP 応答モックは本番の型定義・API 仕様に準拠させ、共通の MSW 定義を再利用する。
- 画面全体の遷移フローは実アプリケーション上で検証し、Storybook 側で複雑な遷移ロジックを再実装しない。
- 実機接続時および本番稼働時は通信モックを無効化し、モックへの自動フォールバックは行わない。

## 実行手順

ツールの採用が正式決定した段階で、Storybook 起動、モック環境でのアプリケーション起動、受け入れテストの実行手順を記載します。
