# モック開発ツール (Mock Tooling)

※ 本書の内容は**提案中（未導入）**です。採否および適合性の検証は [U11](../PLAN.md#u11)、選定の背景は [ADR 0003](ard/0003-select-mock-tooling.md) を参照してください。

## ツール候補と構成案

現行の実行環境には未導入です。設計方針に定める動作確認用 Mock Hub の同梱要件を前提とし、以下の補助ツールを検討しています。

| ツール候補 | 主な用途 | 配置方針 |
| --- | --- | --- |
| Storybook | 本番用 UI コンポーネントおよび画面の各状態を単体表示して確認する | 対象 UI コンポーネントと同一ディレクトリ |
| MSW | HTTP / API 応答をインターセプトしてテスト用データを再現する | モック定義の正本として一元管理 |
| Playwright | 主要シナリオに対するエンドツーエンドの受け入れテスト | テスト配置方針の確定時に決定 |

※ ブラウザと Analytics 間の通信（JSON / SSE）、および Analytics と Hub 間の通信のどのレイヤーをモック化するかは検討中（U11）です。MSW の導入のみを目的とした不要な通信層の追加は行いません。

## 採用時の運用ルール

- 各 Story、モック定義、テストケースは [設計書の重要シナリオ（S1〜S9）](architecture.md#runtime) の ID と対応付けて管理する。
- HTTP 応答モックは本番の型定義・API 仕様に準拠させ、共通の MSW 定義を再利用する。
- 画面全体の遷移フローは実際のアプリケーション上で検証し、Storybook 側で複雑な遷移ロジックを再実装しない。
- 実機接続時および本番稼働時は通信モックを無効化し、モックへの自動フォールバックは行わない。
