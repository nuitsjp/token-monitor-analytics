# ADR-0002: 本番用 UI を共用するモック駆動開発の採用方針

状態: **Proposed** / 提案日: 2026-09-13

## 提案内容

画面のレイアウトや操作フローについて動くモックを用いて事前に仕様合意を形成し、合意済みの同一 UI コンポーネントを実処理へ接続する開発手法を提案します。本プロセスの正式採否および適用範囲は [U10](../../PLAN.md#u10) で判断します。

## 判断理由（4点の説明）

1. **要件・リスク**: 画面レイアウト、インタラクション、表示状態に関して、人と AI の認識の乖離を早期に検知・解消したい。
2. **導入しない場合の問題**: バックエンドの実処理を先行して構築した場合、UI 操作確認の段階で設計齟齬が発覚した際の手戻りと修正コストが過大になる。
3. **単純な代替案との比較**: プロトタイプや使い捨てモックを作成する方式では、本番実装への再実装時に仕様齟齬や意図の抜け落ちが生じる。本番用 UI を共用することで、合意内容を確実に本番へ引き継ぐ。
4. **今検討する理由と負担の受容**: 本格的な UI 実装に着手する前にチーム内の進め方を統一する。一方で、初期段階からモックの保守コストや実環境との差異検証が必要となる点を考慮する。

※ 共通実施手順は [モック駆動開発の共通標準](../standards/mock-driven-development.md)、プロジェクトでの適用状況は [文書方針](../document-policy.md#mock-development) に定めます。補助ツールの選定は [ADR 0003](0003-select-mock-tooling.md) で扱います。
