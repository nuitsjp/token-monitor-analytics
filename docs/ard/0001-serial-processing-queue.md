# ADR-0001: 共通キューによる照合から保存までの直列化

状態: **Adopted**

## 決定内容

SSE による現在値受信と GET による履歴取得は並行して実行しますが、受信完了後のデータ照合、利用許容量の計算、およびデータベースへの保存処理は、共通の単一キューによって1件ずつ直列に処理します。

## 判断理由（4点の説明）

1. **現在の要件・リスク**: 複数 Hub から現在値と履歴を並行受信する構成において、データの照合から保存完了までの整合性を保つ必要がある。特に SSE は利用許容量の推定比較基準を更新し、履歴 GET は実績レコードを更新するため、処理境界の一貫性が不可欠である。
2. **導入しない場合の問題**: 照合開始から保存完了までの間に別の受信によって比較基準が更新され、二重計算やデータの不整合が発生するリスクがある。
3. **単純な代替案が不十分な理由**: SQLite レベルの書き込み排他制御だけでは、アプリケーション層における照合・計算・保存の一連の処理を不可分な処理境界として保護できない。
4. **今必要な理由と負担の受容**: 初期版の現在値保存および画面通知の段階から、一貫した処理境界が求められる。通信待機をキューの外側に配置することで、Hub 間の並行通信を阻害することなく最小限の構成で整合性を担保できる。
