# 照合から保存までを共通キューで直列化する

SSE の現在値と GET の履歴は並行受信するが、受信完了後の照合・計算・保存は共通の単一キューで一件ずつ処理する。

- **現在の要件・リスク:** 複数 Hub の現在値と履歴を並行受信し、照合から保存までの整合性を保つ必要がある。推定の比較基準を更新するのは SSE であり、履歴 GET は保存状態を更新する。
- **追加しない場合の問題:** 照合後から保存までに基準が変わり、重複計算や不整合が生じ得る。
- **単純な案が不足する理由:** SQLite の書き込み競合だけを防いでも、アプリケーション側の照合・計算と保存を一つの処理境界にできない。
- **今必要な理由:** 現在値の保存・通知から一貫した処理境界が必要である。通信待ちはキュー外に置き、Hub 間の通信を並行させる。
