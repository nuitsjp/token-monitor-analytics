# ADR-0001: 共通キューによる照合から保存までの直列化

状態: **Adopted**

## 決定内容

SSE による現在値受信と GET による履歴取得は並行して実行し、受信完了後のデータ照合、利用許容量の計算、DB 保存処理は、単一の共通キューで1件ずつ直列に処理します。

## 判断理由（4点の説明）

1. **現在の要件・リスク**: 複数 Hub からの並行受信において、照合から保存完了までの一貫性を保つ必要があります。特に SSE は推定比較基準、履歴 GET は実績レコードを更新するため、処理境界の整合性が不可欠です。
2. **導入しない場合の問題**: 照合から保存完了までの間に別の受信によって比較基準が更新され、二重計算やデータ不整合が生じるリスクがあります。
3. **単純な代替案が不十分な理由**: SQLite レベルの書き込み排他制御のみでは、アプリケーション層における照合・計算・保存の一連のトランザクションを不可分に保護できません。
4. **現時点で導入すべき理由と負担の受容**: 初期版の現在値保存および画面通知の段階から一貫した処理境界が求められます。通信待機をキュー外で行うことで、Hub 間の並行通信を阻害せず最小限の構成で整合性を担保できます。
