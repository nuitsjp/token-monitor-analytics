# ADR-0003: モック開発補助ツールの選定方針

状態: **Proposed** / 提案日: 2026-09-13

## 提案内容

モック駆動開発を効率的に運用するため、Storybook、MSW、Playwright を組み合わせた構成案を検討します。本システム（UI、JSON / SSE 通信）への適合性検証および採否は [U11](../../PLAN.md#u11) で判断します。

## 判断理由（4点の説明）

1. **要件・リスク**: 本番用 UI の各表示状態の単体確認、API 応答の再現、主要シナリオのエンドツーエンド検証を効率的に反復したい。
2. **導入しない場合の問題**: 特定の異常系や境界状態を再現・確認するために毎回一連の操作を手動で辿る必要があり、検証負担が増大する。
3. **単純な代替案との比較**: 「本番用アプリ ＋ MSW ＋ Playwright」を最小構成案とし、UI コンポーネントを独立して開く価値が高い場合に Storybook を追加する構成とする（独自の状態確認フレームワークは車輪の再発明となるため採用しない）。
4. **今検討する理由と負担の受容**: モック実装を開始する前に、Storybook 導入に伴う設定・Story 保守負担と得られる利点を評価する。現時点で導入を必須化せず、検証を経て採否を決定する。

※ 代表画面を用いて、過大な保守負担なく表示再現と操作検証が可能かを確認した上で採否を判断します。ツール候補の詳細および使用手順は [モック開発ツール](../mock-tooling.md) を参照してください。
