# ADR-0003: モック開発補助ツールの選定方針

状態: **Proposed** / 提案日: 2026-09-13

## 提案内容

モック駆動開発を円滑に進めるため、Storybook、MSW、Playwright を組み合わせた構成案を検討します。本システム（UI、JSON/SSE 通信）への適合性検証および採否は [U11](../../PLAN.md#u11) で判断します。

## 判断理由（4点の説明）

1. **現在の要件・リスク**: 本番用 UI の各状態の単体確認、API 応答の再現、主要シナリオのエンドツーエンド検証を効率的に反復したい。
2. **導入しない場合の問題**: 異常系や境界状態の確認に毎回手動操作が必要となり、検証負担が増大する。
3. **単純な代替案が不十分な理由**: 独自フレームワークの自作は保守負担が過大なため既存ツールを活用。「本番アプリ＋MSW＋Playwright」を最小構成案とし、コンポーネント単体確認の必要性に応じて Storybook を追加する段階的構成とする。
4. **現時点で導入すべき理由と負担の受容**: UI 実装前に設定・Story 保守負担と利点を評価する。現時点では必須化せず、検証を経て採否を決定する。

※ 代表画面での検証を経て採否を判断します。ツール候補の詳細や運用ルールは [モック開発ツール](../mock-tooling.md) を参照してください。
