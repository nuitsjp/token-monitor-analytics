# モック駆動開発の共通標準

標準 ID: `mock-driven-development` / 版: **1**

本書は、UI を伴う機能開発において、動作するモックを用いて仕様合意を形成するための共通標準です。プロジェクトごとの採用状況や適用範囲は各「文書方針」に定めます。

## 1. 適用範囲

- **対象**: UI のレイアウト、操作フロー、表示状態など、画面動作を通じた認識合わせが必要な機能変更。
- **対象外**: 画面を伴わない内部ロジック変更、合意済み仕様のバグ修正、文書のみの改定作業。

## 2. 開発の進め方

機能仕様書を正本とし、同一のモック資産を活用しながら、ユースケースごとに以下の手順で進めます。

1. **シナリオの定義**: 機能仕様書に、初期条件・ユーザー操作・期待結果・未決事項を定義する。
2. **モックの実装**: 本番用 UI を共用し、外部通信等の必要な境界のみをモック化して、同一条件下で反復確認できる環境を構築する。
3. **仕様合意と承認記録**: 確認方法と判断基準を提示して明示的な合意を得て、仕様書に記録する（未合意仕様に依存する実装は行わない）。
4. **実処理への接続と検証**: 合意された UI を実処理へ接続し、期待通りの動作を検証する（重要ケースは自動テスト化）。

## 3. 仕様記述と運用の原則

- **仕様の一元化**: モック専用の仕様書を新設せず、既存の機能仕様書（シナリオ記述）に記録を集約します。
- **モックの境界**: 複雑な業務ロジックやデータ永続化は作り込まず、表示状態の再現に留めます。
- **仕様変更の再合意**: 合意済みの期待結果を変更する場合は、理由と影響範囲を提示して再合意を得ます。
