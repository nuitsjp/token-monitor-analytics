# モック駆動開発の共通標準

標準 ID: `mock-driven-development` / 版: **1**

本書は、UI を伴う機能開発において、動作するモックを用いて仕様合意を形成するための共通標準です。各プロジェクトでの採用状況や適用範囲は各「文書方針」に定めます。

## 1. 適用範囲

- **対象**: UI のレイアウト、操作フロー、表示状態など、実際の画面動作を通じた認識合わせが必要な機能変更。
- **対象外**: 画面を伴わない内部ロジックの変更、合意済み仕様のバグ修正、および文書のみの変更作業。

## 2. 開発の進め方

機能仕様書を合意の正本とし、同一のモック資産を反復利用しながら、ユースケースごとに以下の手順で進めます。

1. **シナリオの定義**: 機能仕様書に、シナリオごとの初期条件・ユーザー操作・期待結果・未決事項を定義する。
2. **モックの実装**: 本番用 UI を共用し、外部通信などの必要な接続先のみをモック化して、同一条件下で反復確認できる状態を作る。
3. **仕様合意と承認記録**: 動作確認方法と判断ポイントを提示し、関係者の明示的な合意を得て仕様書に記録する（未合意の仕様に依存する実装は行わない）。
4. **実処理への接続と検証**: 合意された UI を実バックエンド／実処理へ接続し、同一の期待結果が得られることを検証する。重要な検証ケースは自動テスト化する。

## 3. 仕様記述と運用の原則

- **仕様の一元化**: モック専用の仕様書を新設せず、既存の機能仕様書（シナリオ記述）に初期条件、操作、期待結果、承認記録、対応テストを追記します。
- **モックの境界**: モック側に複雑な業務ロジックや高度なデータ永続化を作り込まず、表示状態の再現に留めます。
- **仕様変更の再合意**: 合意済みの期待結果を変更する場合は、理由と影響範囲を明示して再合意を得ます。
