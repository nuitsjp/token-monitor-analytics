# モック駆動開発

標準 ID: `mock-driven-development` / 版: **1**

採用版・適用状態と、仕様・ツール・ADR の配置は各プロジェクトの文書方針で定める。以下は採用後の実施ルールとする。

## 適用範囲

画面・操作・表示状態について、動くものによる認識合わせが必要な変更に適用する。内部変更、合意済みの振る舞いを回復する修正、文書だけの作業は対象外とする。

## 進め方

機能仕様を合意の正本とし、既存の合意・モックを再利用する。一つの利用目的ごとに進める。

1. シナリオの初期条件・操作・期待結果・未決事項を仕様に記す。
2. 本番用 UI を共用し、必要な接続先の応答だけをモックにする。同じ初期状態から繰り返し確認できるようにする。
3. 確認方法と判断してほしい点を提示し、人の明示的な承認を仕様に記録する。未合意事項に依存する実処理は進めず、独立した作業を続ける。
4. 合意した範囲を実処理へ接続し、同じ期待結果で確認する。重要な期待結果は自動テストに残し、実接続での未検証範囲を明記する。

仕様は利用目的・範囲と、シナリオ ID ごとの**初期条件・操作・期待結果・未決事項・合意・確認入口・対応テスト**を持つ。承認記録には日付・範囲・根拠への参照を残す。既存仕様へ追記し、モック専用の仕様を重複して作らない。

合意済みの期待結果を変える場合は、理由と影響を示して再合意する。モックに複雑な業務処理や永続化を作り込まない。

ツールの利用・設定時だけ製品固有の手順を、方針変更の検討時だけ関連 ADR を参照する。
