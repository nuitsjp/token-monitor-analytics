# Token Monitor Analytics

Token Monitor Analyticsは、[Token Monitor](https://github.com/Javis603/token-monitor)が収集したAIツールの利用量・API換算額・サブスクリプション利用率を継続的に蓄積し、分析・可視化するための非公式コンパニオンアプリケーションです。

Windows向けのネイティブデスクトップアプリケーションとして、Wails v3、Goバックエンド、Webフロントエンドを使用して実装します。

## 背景

Claude Code、Codex、Cursor、GitHub CopilotなどのAIサブスクリプションでは、一定期間内の利用枠が提供されています。

しかし、多くのサービスでは利用枠が金額ではなく、利用率、トークン、リクエスト数、クレジット、一定期間の制限などとして表示されます。そのため、契約によって実質的にどの程度のAPI利用価値が提供されているのかを、サービス間で直接比較することは困難です。

Token Monitorは、複数のAIツールについて以下の情報を取得できます。

* 実際に使用したトークン数
* モデル別のAPI換算利用額
* サブスクリプションの利用率
* 利用枠のリセット日時
* ツール、モデル、デバイスごとの利用状況

一方、Token Monitorは、API換算利用額と利用率を組み合わせてサブスクリプションの推定上限額を算出し、その推移を長期的に保存することを主目的としていません。

Token Monitor Analyticsは、この不足部分を補完します。

## 最重要ゴール

本プロジェクトの最重要ゴールは、各AIサブスクリプションについて、契約上利用できたと推測されるAPI換算上限額を継続的に算出し、その推移をトレースできるようにすることです。

推定上限額は、同じ利用枠に属するAPI換算利用額と、ベンダーが報告する利用率から算出します。

```text
推定API換算上限額
= 対象期間内のAPI換算利用額 ÷ 利用率
```

例えば、ある週次利用枠について、API換算で800ドル相当を使用した時点の利用率が40%だった場合、推定上限額は次のようになります。

```text
800 USD ÷ 0.40 = 2,000 USD
```

これは、その時点までと同じモデル構成や利用傾向が続いた場合に、そのサブスクリプションで約2,000ドル相当のAPI利用が可能だったと推測するものです。

この値はベンダーが保証する正式な契約金額ではなく、実際の利用実績に基づくAPI換算上の推定値です。使用するモデルやトークン構成が変われば、同じ契約でも推定値は変動します。この変動を含めて継続的に記録・観測することを、本プロジェクトの重要な価値とします。

## 目的

Token Monitor Analyticsでは、以下を実現します。

* Token Monitorの認証付きHub APIへ接続する
* API換算利用額、利用率、利用枠、リセット日時を定期的に取得する
* プロバイダー、アカウント、利用枠ごとに観測データを保存する
* API換算利用額と利用率の対象期間を一致させる
* サブスクリプションの推定API換算上限額を算出する
* 推定上限額の時間的な変化をグラフで確認する
* 実際の利用額、推定上限額、残存価値、契約料金を比較する
* 複数のAIサブスクリプションを横断的に分析する
* Token Monitorが収集する各種データを、分析用ダッシュボードとして閲覧する

## 分析対象

サブスクリプションには、複数の独立した利用枠が存在する場合があります。

例えば、Claude Codeには5時間枠と週次枠があり、他のサービスにも日次、週次、月次、請求期間、クレジットなどの異なる制限があります。

Token Monitor Analyticsでは、これらを個別の利用枠として扱います。

```text
プロバイダー
  └─ アカウント
      ├─ セッション／5時間枠
      ├─ 日次枠
      ├─ 週次枠
      ├─ 月次枠
      └─ 請求期間枠
```

推定上限額は、利用枠ごとに独立して計算します。週次利用率に対して月間のAPI換算利用額を使用するなど、異なる期間のデータは組み合わせません。

## 主な表示・分析機能

### 推定上限額の推移

プロバイダー、アカウント、利用枠ごとに、以下の推移を表示します。

* API換算利用額
* ベンダー報告の利用率
* 推定API換算上限額
* 推定残存API換算額
* 利用枠のリセット日時
* 観測日時
* 推定値の変動幅

### サブスクリプション価値の評価

実際の契約料金を登録し、次の指標を表示します。

```text
実利用価値倍率
= 実際のAPI換算利用額 ÷ 契約料金
```

```text
推定最大価値倍率
= 推定API換算上限額 ÷ 契約料金
```

これにより、「実際にどれだけ利用したか」と「契約上どこまで利用できたと推測されるか」を分けて評価します。

### その他の分析

将来的には、Token Monitorが提供するデータを利用して、以下の分析にも対応します。

* 日別、週別、月別のAPI換算利用額
* ツール別、モデル別、デバイス別の利用状況
* サブスクリプション間の利用価値比較
* 利用枠の消費速度
* リセット時点までの利用率予測
* 未使用のまま失効した推定API換算額
* モデル構成による推定上限額の変化
* 過去の利用周期との比較
* 契約プラン変更前後の比較

## データ保存

初期バージョンでは、すべてのデータをローカルデータベースへ保存します。

保存対象には、少なくとも以下を含めます。

* Token Monitorから取得した観測時点のスナップショット
* プロバイダーとアカウントの識別情報
* 利用枠の種類
* 利用枠の開始日時とリセット日時
* API換算利用額
* 利用率
* 推定API換算上限額
* 契約料金
* 算出条件とデータ品質
* 取得日時と計算日時

取得した元データと算出後の分析データを分離して保存し、計算方法を変更した場合に再計算できる構造とします。

## クラウド対応

将来的には、ローカルに蓄積したデータをクラウドへ保存し、Webブラウザや複数端末から閲覧できる機能を追加します。

クラウド連携はオプション機能とし、利用しない場合でもすべての主要機能がローカルだけで完結する設計とします。

```text
Token Monitor
      ↓
Token Monitor Analytics
      ↓
ローカルデータベース
      ↓ 任意
クラウドストレージ／分析サービス
      ↓
Webブラウザ・別端末
```

クラウドを利用するかどうかは利用者が明示的に選択できるものとし、クラウド接続を必須要件にはしません。

## アプリケーション構成

初期バージョンは、Windows向けのネイティブデスクトップアプリケーションとして実装します。

* アプリケーションフレームワーク：Wails v3
* バックエンド：Go
* フロントエンド：Web技術
* データ保存：ローカルデータベース
* データソース：Token Monitor Hub API
* 対象OS：Windows

GoバックエンドがToken Monitorとの接続、定期収集、データ保存、集計、推定値の計算を担当します。Webフロントエンドは、設定画面、ダッシュボード、グラフ、比較画面などを提供します。

## 開発フェーズ

### Phase 1：ローカル収集と推定

* Token Monitor Hubへの接続設定
* 認証付き`GET /api/stats`の定期取得
* ローカルデータベースへのスナップショット保存
* プロバイダー、アカウント、利用枠の識別
* 対象期間内のAPI換算利用額の算出
* 推定API換算上限額の算出
* 推定上限額の履歴表示

### Phase 2：分析機能

* サブスクリプション料金の登録
* 実利用価値倍率の表示
* 推定最大価値倍率の表示
* サブスクリプション間比較
* 利用額、利用率、推定上限額のグラフ表示
* モデル別、ツール別、デバイス別分析
* CSVおよびJSONエクスポート

### Phase 3：オプションのクラウド連携

* クラウド保存先の設定

* Webダッシュボード
* バックアップと復元

## 対象外

初期段階では、以下を対象外とします。

* ベンダー内部の料金計算方法を完全に再現すること
* 非公開の割引、優遇、補正係数を追跡すること
* 推定上限額を正式な契約上限として保証すること
* Token Monitor自体の利用量収集機能を置き換えること
* クラウドサービスの利用を必須とすること
* Token Monitorが取得できない利用量を独自にスクレイピングすること

ベンダー固有の詳細な割引を再現するのではなく、Token Monitorが算出したAPI換算額と、ベンダーが報告した利用率を共通の評価材料として使用します。

## プロジェクト方針

Token Monitor Analyticsは、以下の方針を重視します。

1. 推定API換算上限額の推移を最優先で記録する
2. ローカルファーストで動作する
3. 元データと計算結果を分離して保持する
4. 計算根拠を確認できるようにする
5. プロバイダーごとの差異を吸収しつつ、無理な共通化はしない
6. クラウド連携は任意とする
7. Token Monitorを収集基盤として活用し、既存機能を重複実装しない

## 位置付け

Token MonitorがAIツールの利用状況を収集・表示するモニターであるのに対し、Token Monitor Analyticsは、そのデータを長期保存し、サブスクリプションの価値と推定利用上限を分析するアプリケーションです。

```text
Token Monitor
= 利用状況と利用枠を収集する

Token Monitor Analytics
= 収集されたデータを蓄積し、推定・比較・分析する
```

本プロジェクトはToken Monitorの非公式な関連プロジェクトであり、Token Monitor本体およびその開発者による公式製品ではありません。
