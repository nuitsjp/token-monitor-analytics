# Token Monitor Analytics

Token Monitor Analytics は、複数の [Token Monitor](https://github.com/Javis603/token-monitor) Hub から定額制 AI サービスの利用実績や利用枠を収集し、実測増分に基づいて利用許容量（米ドル換算の参考値）を推定・保存するセルフホスト型ダッシュボードです。

## プロジェクトの現状

全サービスに共通の利用許容量推定を実装しました。サービス名の固定一覧や個別の契約検証を前提にせず、Hubが報告する利用額・利用枠・更新状態から推定可否を判断します。割合、残量率、使用量と上限を同じ消費率へ正規化し、枠ごとに参考値を算出します。取得不能・stale・切断等の端末は推定から除外し、残る有効データで算出した参考値と除外理由を表示します。148件の自動テスト、schema 6への実DB・Mock移行と履歴保持、Private・Workの実データ再起動、headless Edgeの実データ画面を確認済みです。

現在値の受信・SQLite 保存・Web 表示・自動再接続に加え、従来のHub単位のSSE現在値からの利用許容量推定、推定結果・理由・根拠の保存と履歴閲覧を実装しました。Mock Hubによる自動テストとWindowsのChromeで表示・継続更新・再接続を確認済みです。Private・Workの実Hubへの同時接続・保存と、利用者による実データ表示も確認しました。別端末からのLAN経由の画面表示・継続更新も利用者が確認済みです。利用枠は残量（未使用100%起点）として表示し、未設定の取得元は既定で隠してトグルで表示できます。画面最上段には全Hubの利用額・トークン数を期間別に集計した全体メトリクスを表示し、各Hubの最終更新日時も表示します。Cursorは各端末へ同じアカウント全体実績が配信されるため、同じ契約集合の重複報告を期間ごとに除去します。この補正により、全体値はHub表示値の単純和と異なる場合があります。Hub横断の共通契約を一件として扱う推定、端末・契約の多対多関連、共通契約カードと全体推定、共通・旧方式を分ける履歴APIはコード、自動テスト、実DB・Mock適用、headless Edge検証まで完了しました。日次・月次履歴、WebからのHub管理、手動更新は未実装です。実装の未検証範囲は [PLAN.md](PLAN.md) を参照してください。

Grokは同じメールアドレスの報告をHub横断で一つの契約カードにまとめます。トークンの更新でカードは増えず、メールアドレスが変わった場合は別契約として保持します。既存DBの契約関連も更新し、観測・推定履歴は保持します。Claudeの組織別契約を識別するための取得項目は [Issue #34](https://github.com/nuitsjp/token-monitor-analytics/issues/34) で確認する課題として残しています。

なお、初期版は限定された安全なネットワーク環境での利用を想定しており、ダッシュボード自体の利用者認証は後続実装とします（Hub への接続には共有シークレットを使用）。

## Windows で動かす

Node.js 24 と mise を使用します。リポジトリのルートで `npm run setup` を実行すると、待受設定と空の Hub 設定ファイルを作成し、秘密情報を置くフォルダーのアクセス権を設定します。既存設定は上書きしません。

用途に応じて、次のどちらかを起動します。

| 用途 | コマンド | 接続設定 | 保存先 |
| --- | --- | --- | --- |
| 実データ | `mise run real` | `.local/hubs.json` に実 Hub を記入 | `data/real/analytics.sqlite` |
| Mock | `mise run mock` | 内蔵 Mock Hub を自動起動。実 Hub の設定は読み込まない | `data/mock/analytics.sqlite` |

同時起動はできません。切り替えるときは、起動したターミナルで Ctrl+C を押して終了してから、もう一方を実行します。Mock Hub も一緒に終了します。両方とも `.env` の待受設定を使うため、開くURLは共通です。既定は [http://127.0.0.1:3000](http://127.0.0.1:3000) で、画面とタブ名に起動モードを表示します。

テストは `npm test` で実行します。外部 npm 依存はありません。`npm start` と `npm run start:mock` もそれぞれ同じ実データ用・Mock用の起動処理を使います。

実 Hub への切り替え、LAN 待受、設定例、ログと復旧の手順は [設計書 第7節](docs/architecture.md#7-配置と運用-deployment-view) に記載しています。

## 初期版の提供機能

- 利用枠・消費率・API 換算額および取得状態の可視化
- 全サービス共通の実測増分に基づく利用許容量の推定と保存・履歴閲覧（同じ `provider + accountKey`、Grokは同じ正規化メールをHub横断で一契約として扱う。Cursorのアカウント全体実績は同じ契約集合ごとに一度だけ数え、取得不能な端末を除外した場合は部分推定として表示する。通常は基準プラン・倍率の設定不要で、異なるプランの共有利用額をまとめて推定する場合だけ共通設定を使う。枠ごとの推定値は合算しない）
- 日次・月次実績の定期収集、過去データの補完、推移の比較表示
- 複数 Hub の一括管理（登録、並行収集、状態監視、個別停止・再開）
- 手動更新機能、管理操作の入力検証・CSRF 対策、障害時の復旧情報提示
