---

必須構造は [設計・文書標準](../../../docs/standards/design-and-documentation.md#usecase-documents)、案の確認と保存は [モック標準](../../../docs/standards/mock-driven-development.md#discussion) に従う。既存仕様の移設では内容を保持する。

新規作成時は [ユースケース雛形](assets/usecase.md) と [シナリオ雛形](assets/scenario.md) を使用する。雛形は実仕様ではない。任意項目と種別に該当しない条件欄を除き、合意した内容を記入して所定の名称のパスへ保存する。所属は配置から決まり、ID項目を追加しない。

シナリオ追加時は親の一覧へ個別リンクを追加する。固有の条件・手順・受け入れ条件はシナリオに集約し、親には共通事項を残す。改名・移動時は文書とテストの参照も更新する。

プロジェクトルートで `python scripts/doc_check.py .` を実行する。形式の合格だけで仕様の妥当性や利用者の承認を判断せず、変更前後の条件・動作・期待結果も照合する。
